# Lesson 8: Design and Test an Improvement

## Why This Matters

A paper sketch is faster and safer to change than code. You can compare ideas
and test whether people understand them before asking anyone to implement one.

## Start With Evidence

Copy your Lesson 7 problem statement:

```text
User:
Goal or task:
Observed difficulty:
Context:
```

Choose a problem small enough to improve one screen or one short workflow.

## Sketch Two Ideas

For each idea, draw:

- The information the user needs first.
- Controls the user can act on.
- Representations such as labels, icons, colors, and highlights.
- Feedback shown after the action.
- A recovery option for a likely mistake.

Do not worry about artistic quality. Boxes, arrows, and readable labels are
enough.

## Explain the Interaction

Complete this for each sketch:

| HCI question | Answer |
| --- | --- |
| What is the user's goal? |  |
| What action can the user take? |  |
| What signals that the control is interactive? |  |
| What does the interface represent? |  |
| What feedback follows the action? |  |
| What error is possible? |  |
| How can the user recover? |  |
| Does it work without relying only on color? |  |

## Test the Paper Interface

Give a partner the same scenario used in Lesson 7. Place your sketch in front
of them. When they point to a control, act like the computer by showing or
drawing the next state.

Do not defend the design while they test it. Record:

- The first thing they noticed.
- Where they expected to tap.
- Any words or symbols they misunderstood.
- Whether feedback answered “What happened?”
- Whether recovery was easy to find.

## Decide What to Keep

Use this decision statement:

```text
We will try [specific design change] for [user and task].
We chose it because [observation from testing].
We will know it helps when [observable success condition].
We will preserve [important existing behavior].
```

Example success conditions include fewer wrong selections, a shorter pause, or
correct understanding without help. “Looks better” is difficult to test.

## Checkpoint

- [ ] I drew two possible designs.
- [ ] Both designs include feedback and error recovery.
- [ ] Another person attempted a task with one design.
- [ ] I changed or selected an idea using observation evidence.
- [ ] I wrote one measurable success condition.

If your class is not using AI, your teacher may assign a manual implementation
or another design iteration. If your class is using Copilot, continue to
[Lesson 9: Copilot Setup and Safety](09-copilot-setup-and-safety.md).
